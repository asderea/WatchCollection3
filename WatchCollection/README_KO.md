# Watch Collection v0.4

개인 시계 컬렉션, 오차, 착용 기록, 스트랩을 한 앱에서 관리하는 Android 앱입니다.

## v0.4 핵심 변경: 스펙 검색 정확성 우선

### 1. 사진 자동 검색 제거
- 시계 대표사진은 더 이상 웹에서 자동으로 가져오지 않습니다.
- 시계 추가/수정 화면에서 `대표 사진 선택` 버튼으로 휴대폰 사진을 직접 지정합니다.
- 선택한 사진은 앱 내부 저장소로 복사되어 컬렉션, 캘린더, TOP3, 스트랩 호환 시계 영역에 동일하게 표시됩니다.

### 2. 스펙 검색 엔진 재설계
- 레퍼런스 번호가 있으면 모델명보다 레퍼런스 exact match를 최우선으로 사용합니다.
- 제조사 공식 사이트를 가장 높은 신뢰도로 사용합니다.
- 공식 페이지에 없는 항목은 WatchBase / Caliber Corner / WatchCharts 등 고신뢰 시계 DB와 전문 매체, 검증된 판매처를 단계적으로 사용합니다.
- Bing RSS 한 종류에만 의존하지 않고 DuckDuckGo Lite 검색도 보조 검색으로 사용합니다.
- 검색 결과 제목만 믿지 않고 실제 페이지 본문과 JSON-LD Product의 브랜드/모델/SKU를 다시 확인합니다.
- 레퍼런스가 입력된 경우 비공식 페이지는 실제 본문에 같은 레퍼런스가 있어야 스펙 후보가 됩니다.
- 공식 페이지가 접근 차단된 경우에도 exact reference가 명확한 공식/고신뢰 DB 검색 스니펫만 제한적으로 보조 근거로 사용합니다.

### 3. 필드별 교차검증
다음 스펙을 필드별로 따로 검증합니다.
- 무브먼트
- 칼리버
- 직경
- 러그투러그
- 두께
- 러그 폭
- 파워리저브
- 방수
- 글라스
- 케이스 소재

공식 페이지에서 명확하게 확인된 값은 우선 사용합니다. 공식에 없는 값은 높은 신뢰도의 단일 데이터베이스 또는 서로 다른 복수 출처가 같은 값을 제시할 때만 자동 입력합니다. 기준을 통과하지 못한 값은 잘못된 숫자를 억지로 넣지 않고 빈칸으로 둡니다.

### 4. 제조사별 표기 차이 대응
- Seiko: `Caliber Number`, `Distance between lugs`, `Lug-to-lug`, `Duration` 등
- Hamilton: `Case size`, `Thickness (mm)`, `Lug width`, `Power reserve` 등
- Mido: `Width (mm)`, `Case length (mm)`, `Average Thickness (mm)`, `Lug` 등
- 한국어 공식 페이지의 `지름`, `러그 넓이`, `러그 사이의 거리`, `평균 두께`, `무브먼트 유형`, `크리스탈` 등도 인식합니다.

## 기존 v0.3 기능 유지
- 하단 컬렉션/오차/캘린더/스트랩 아이콘
- 캘린더 올해 TOP3 / 이번 달 TOP3 스와이프 카드
- TOP3, 캘린더, 스트랩 호환 시계 → 컬렉션 해당 시계 바로가기
- 시계 카드 올해/이번 달/전체 착용 횟수
- 하루 최대 두 시계 착용 기록
- 하루 두 시계를 기록하면 각각 0.5회로 계산
- 날짜 셀에 최대 두 시계 사진 표시
- 18/19/20/21/22 mm 스트랩 필터 및 해당 러그 폭 시계 상단 표시

## 데이터
DB 구조는 v0.3과 호환되므로 기존 컬렉션/오차/착용/스트랩 기록을 그대로 사용할 수 있습니다. v0.4 APK는 동일한 debug signing key를 사용해 v0.3 위에 덮어설치할 수 있도록 구성되어 있습니다.

## GitHub Actions 빌드
`.github/workflows/build-apk.yml`은 저장소 안에서 `settings.gradle` 위치를 자동 탐색합니다. 따라서 실수로 프로젝트 폴더가 한 단계 더 들어가도 Gradle 프로젝트를 찾아 빌드하도록 보강했습니다.

1. ZIP 내용물을 GitHub 저장소에 업로드합니다.
2. Actions → `Build Watch Collection APK`를 실행합니다.
3. 성공 후 `WatchCollection-v0.4-debug-apk` artifact를 받습니다.

## 정확성 정책
웹사이트 개편, 지역별 공식 페이지 차이, 봇 접근 차단 때문에 어떤 모델도 100% 자동 검색을 보장할 수는 없습니다. v0.4는 이 상황에서 틀린 값을 채우는 대신 검증할 수 없는 항목을 빈칸으로 두는 방향을 선택합니다. 특히 레퍼런스 번호를 함께 입력하면 검색 정확도가 크게 올라갑니다.
